# 管理员私聊视频指令

在管理员本人的QQ私聊发送；当前支持B站长链、b23.tv短链及BV号。

- `[视频帮助]`：查看指令与额度说明。
- `[分享视频 链接 谁]`：向指定目标发送QQ原生分享卡片（标题、封面、可点击视频链接）；有本次管理员或目标会话可用的已读资料时复用后自然分享。
- `[观看视频 链接 谁]`：先分析受限采样画面/可用字幕，再按当前QQ人物卡通过原生卡片自然分享。不宣称逐帧或完整看完。
- `[刷B站 谁]`：沿用推荐/人物兴趣浏览，选到合适视频后分享给目标。
- 省略“谁”发回管理员本人私聊；`[分享B站]`保持兼容。

示例（替换链接与号码，不要原样发送占位符）：

```text
[分享视频 https://www.bilibili.com/video/BVxxxxxxxxxx group:群号]
[观看视频 BVxxxxxxxxxx private:QQ号]
[分享视频][https://b23.tv/短链][完整群名或好友备注]
[观看视频][这个视频][游戏群]
[刷B站][group:群号]
```

目标沿用现有群名、好友备注、绑定别名解析；也可明确使用`group:群号`、`private:QQ号`、`群123456`、`私聊123456`。含空格名称使用分括号写法。裸号码沿用群列表识别；重名、无法确认类型或白名单外目标拒绝，不能靠指令扩白名单。跨会话控制只接受管理员本人私聊。

观看按目标会话计用户视频额度：每私聊6条/北京时间日、每群9条/日，失败尝试计额，复用不计额；不占主动浏览6条。`刷B站`仍与自动浏览共用全局每日深读6条。手动指定分享不占主动分享限额，仍守暂停、撤权、人物卡变更、媒体资源和QQ发送限流。发送回执不明不自动重发。

个人视频资料仍按说话人、会话、当前人物卡隔离；本管理员显式指定分享时可携带本人本会话的公开视频观看资料，仅确认投递后成为目标会话共享资料。群中他人的私有资料不能因此读取。摘要过期、切卡或无权复用时不隐式重读；没有观看资料/媒体额度失败时不假报已观看。

原`[看视频][链接][问题]`和视频追问仍为本会话提问，“问题”不当成转发目标。新控制入口不伪造目标用户消息，不额外唤醒DSH，不更改原消息/队列；短期资料不入长期或向量记忆。B站评论、回复、私信、点赞、投币、关注等写操作保持禁用。


电脑/手机复制出的带标题文本可直接放入指令，无需手动删标题或跟踪参数，例如`[分享视频 【视频标题】 https://www.bilibili.com/video/BVxxxxxxxxxx/?share_source=copy_web group:群号]`；分P参数保留。一次多个链接会拒绝。

管理员本人私聊中，引用B站视频卡片/视频链接消息后，可直接说`分享到游戏群`、`分享给好友备注`、`把这个视频发到group:群号`；也可`[分享视频 群名或好友备注]`。引用必须确属当前私聊；不使用别的会话原消息，不把无引用的“发给某人”误当视频指令。只从引用中提取公开视频链接，不搬运整个卡片JSON或其中不可信字段。

手动、观看后和自动分享都使用完整JSON/Ark视频卡片，标题与封面来自B站真实元数据；感想放在卡片摘要。旧缓存缺标题/封面时允许补读元数据，不重复下载/分析视频。发送仍沿用同会话发送队列、节奏、权限检查和额度；无有效消息ID不报成功，不自动重发或降级裸链接。消息提交成功不等于已人工核实所有QQ客户端的显示样式。


总结与时间点追问：已有视频资料时，可直接说“总结一下那个视频”“有没有时间戳，各时间点在说啥”“01:23在讲什么”“第2分钟怎么做的”；引用机器人一句普通聊天也会在检查引用归属后接续当前视频，不将那句聊天当作新视频。不覆盖明确引用的另一条视频；无可复用资料时说明缺口，不借其他人的私有资料。

这些自然追问复用已有采样资料，不重下视频、不重新调用视频模型、不扣视频分析额度，也不进入视频分析15秒冷却。初次视频分析已经生成按真实采样帧绑定的[MM:SS]画面依据；角色按实际时间戳回答。采样不是完整逐秒台词，没有时间信息或未覆盖的时段如实说明。跟进消息保留用户本轮问题，不再伪装成“又发了一个视频”。缺少原视频而未开始分析的失败不再占用视频额度/15秒冷却。

## 已读视频推荐的延迟感想（2026-11-03）

主动推荐、刷B站、观看后分享和有效缓存资料的分享：先发标题/封面/链接图文，确认会话历史送达后等待随机2–3秒，再单独补一条当前人物卡的自然感想。复用原有一次composeShare文本，不重看、不增加模型调用；只转发未读链接时不假装已观看，仍只发图文。

感想按本次证据挑一两个具体细节，再接人物自己的喜恶、吐槽、联想或取舍，通常80–220字，可分一两小段；不复述内容提纲、不固定套反问/排队/美食示例，不编亲历。两个消息占QQ两条发送额度，但仍只算一次视频分享；预留整组发送额度，同一发送队列内按序投递。暂停、切卡或目标权限变化后取消未发感想；图文未确认时不发送感想；第二条失败不把第一条报失败、不自动重发整组。

## 来信视频自动读取（2026-11-03，按用户新要求覆盖旧的群无@规则）

在当前已授权的私聊/群聊里，任何成员直接发送QQ视频附件、支持的视频分享卡片（JSON/XML/share）或可识别视频链接，均自动尝试读取，不要求群内@机器人。此处“自动”属于用户来信视频，B站仍按每私聊6条、每群9条的独立日额度，不占主动刷B站全局深读6条；资源不足、单任务繁忙、暂停、权限关闭时明确失败，不冒称看过。未知网页卡片不因标题像命令而执行；实际附文说不要看时不处理。

JSON/XML/share的视频分享信息会转成平台、标题及去跟踪参数的公开链接给角色，而非只显示[卡片消息]；标题只是分享元信息，不能冒充画面。视频内容来自实际读取结果，保留采样限制、角色/会话/说话人隔离、结果复用和私人周记保护。链接预览只处理真实text段，不对从卡片转出的链接重复抓预览。

## 读取中状态与群聊能力判断（2026-11-03）

收到卡片后后台下载/分析需要时间。角色查询未读或构建唤醒上下文时，当前发言人正在处理的视频会附status=processing，明确是仍在读取，不等于不支持卡片；不要让用户重复发视频或改发文件。实际结果回来后为status=ready，按本次采样事实回答，不能继续沿用历史中“卡片摸不到画面”的旧判断。

状态按发言人/会话隔离；新的读取中状态优先于该人的旧视频结果。桥接重载后可从现有持久B站结果恢复15分钟内的同范围短期资料，仍区分画面与元数据，损坏的可选缓存不阻断普通聊天。超过15分钟不自动注入，明确总结/追问仍走原有受限复用。未改每日额度、未重跑原视频。

## 等视频时的自然接话（2026-11-03）

processing仅为内部状态，不作为进度播报模板。默认不发视频相关的过渡话，等读取完成后直接回答原问题。每次视频任务开始时固定抽一次，约15%机会给角色interimReplyAllowed=true；允许不代表必须回应。提示约束同条视频最多一次一句，可自然说“等我看看”“看完告诉你”，不拆两条，不照搬后台状态、不让用户透底、不拿标题猜内容。该选择在同一任务里保持稳定，不因轮询或追问重复抽样。

这是角色应答策略提示，未新增僵硬的关键词删句/拦截器；普通聊天与完成后的真实内容回复保持原流程。不新增模型调用、视频分析或额外QQ测试消息，额度不变。

## 视频资料最多3天，重要对话记忆独立保留（2026-11-03，覆盖旧6小时/7天策略）

视频资料缓存按实际分析完成时间最多保留72小时，含摘要、采样时间点、标题/封面/覆盖说明；重复分享或检索不顺延这个上限。自动注入聊天仍只15分钟，之后仅在用户明确提起旧视频、引用或给链接/BV时取对应资料；按标题/日期筛选，多条候选要澄清，不把最近一条强行当作所问视频。

B站独立video-seen.json只保存BV+分P与首次/最近分析时间，长期去重，不保存标题、字幕、摘要或私人问题。新日常备份包含这个最小索引，不包含视频内容缓存。旧缓存迁移保留原分析时刻，已被旧6小时策略删除的摘要不会自动补看恢复。资料容量仍有上限（512条记录、最多256份摘要、已读索引5万条），索引满或损坏时失败关闭，不静默丢标记再收费分析。

跨会话只复用中性默认概括、且通过无登录公开元数据校验的B站资料；私人提问分析/人物感想不进入公共事实池，旧缓存默认不升级为公共内容。只知道已读而无资料时不自动重读扣额；显式[重新看视频][链接或BV]才重新分析并使用原有当日额度。[分享视频]纯转发不因旧摘要过期被拒绝。主动候选也会提前跳过只有已读标记而无资料的旧片。

原片/帧图不长期保留；QQ附件和其他平台沿用更短的15分钟临时上下文，未把私聊附件纳入公共事实缓存。这里限制的是应用视频资料缓存，不改写原始聊天历史，也不清理对话中已有的重要记忆、人物卡或任务。缓存到期后不能再被调用，现有后台tick负责清理，关闭扩展功能也会做保留检查；没有新增并发写同一JSON的后台服务。
