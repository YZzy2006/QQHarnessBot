# 运行报错与QQ管理入口

## 报错去向

桥接运行报错、回合处理失败、watchdog卡住告警和定时任务失败统一写入原受保护的反馈档案，在工作台「反馈 / 需求」显示为**系统报错**。不再主动发管理员QQ私聊或其他QQ会话，不会因工作台写盘失败而回退到QQ发送。

原服务日志保留；反馈中记录经过脱敏、长度限制的错误摘要、来源和时间。相同错误5分钟去重，最多20条／分钟、100条／小时，档案沿用500条上限，防止故障洪峰刷盘。反馈读取需管理权限，QQ会话智能体不能读取；错误档案不进入聊天记忆。

普通任务提醒、正常对话、操作结果与好友／空间业务通知保持原逻辑，不能把报错静默误改成禁止发送所有消息。工作台既有「最近错误」查询仍可读取原服务日志。

## 对应管理功能留在工作台

配置了`workbench.origin`时，QQ里的系统查询、运维读取、帮助菜单和既有斜杠管理入口静默，继续使用对应的工作台结构化操作。包括状态、服务器、用量／余额、备份／错误／会话列表和帮助菜单。内部处理器没有删除，工作台仍可以调用。

没有配置工作台的独立部署保留普通文字管理命令的原有权限与确认机制；不要为禁用QQ诊断而把正常管理功能变成不可用。无论工作台是否配置，`#sl`等显式机器探测都没有管理员豁免。

天气、自然语言提醒、定时任务及其业务指令继续使用原入口。普通文字帮助不是SnowLuma内置协议；只有明确迁移到工作台的入口才在QQ侧关闭。

## 部署和验收

使用匹配机器人和前端资源；无新依赖或数据库迁移。保留现有state、任务、人物卡、QQ登录和账号配置，只更新对应源码。工作台只显示之后实际发生的错误，部署不要伪造真实错误或发送QQ测试消息。

运行`npm run test:incoming`及工作台回归：用隔离FakeBot验证所有模式零QQ报错通知、错误写盘／脱敏／去重、工作台鉴权可见、QQ入口静默而内部管理可用、正常任务仍能创建。**禁止在真实QQ发送测活指令验收。**
