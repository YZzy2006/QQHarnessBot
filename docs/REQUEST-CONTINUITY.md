# 连续追问与位置卡片

地点查询后5分钟内，同一会话同一发言人可以说“换腾讯的”“选第二个”“发这个”或“再来一个”。
查询条件、候选和选择仅在进程内短期保存；不同成员、不同会话不能复用对方的地点ID。
普通查询不自动发卡，多候选且尚未选择时会要求选择。明确索要卡片时按查询结果提交候选。

地图指定来源表示优先，失败、无结果或额度限制时按其他可用来源兜底。
腾讯 `121` 被归类为日额度耗尽，响应和文字必须说明实际来源，不能把高德结果称为腾讯结果。
卡片上游回执不明时不自动重发，不降级为长链接；部分提交成功时说明数量。
同次入站请求的重试去重只在当前进程和有效窗口内生效，不承诺跨重启恰好一次。

已识别的工具请求按会话与发言人进入有界队列，每主体1个执行中、最多4个等待。
等待超过2分钟的请求不执行并给出说明；前条失败后继续后条。
任意自然语言承诺仍由原模型与会话机制处理，不存在后台模型循环自动追踪所有口头任务。

检查位置卡片时，应同时查看本次查询的 `delivery.status`、`placeIds` 和出站回执。
没有单独的 `qq_send_location` 工具调用，不代表后端查询没有自动提交卡片。
QQ 客户端的实际显示和坐标点击仍需单独验收。
