# QQ入站显式机器探测策略

SnowLuma的`#sl`是网关内置状态指令，可能在桥接之前直接回复。应在部署者自己的默认和每账号配置中将`statusCommand.enabled`设为`false`，核对最终合并值；`swallow`或增加冷却不能代替关闭回复。只修改这一字段，保留网络节点、令牌和登录数据。独立网关进程可受控重载，不要因此重启QQ或重建容器。

桥接在引用／媒体／业务命令／未读／模型之前静默拦截显式机器格式，如`#sl`及标点／大小写／全角／零宽变体、`.status`、`#ver`、`#info`、`#test`和未知调试斜杠命令，对管理员也适用。普通聊天中讨论这些字符串不会据此执行诊断。

普通中文、方括号管理入口不是一概禁止。配置了工作台时，将已有对应功能的系统／诊断／菜单与斜杠管理入口转移到工作台；没有配置工作台的部署保留正常管理权限。天气、提醒和定时任务不误伤。见[运行报错与入口说明](OPERATIONAL-ERRORS.md)。

配置片段仅作字段示意，不可覆盖整个配置：

```json
{"statusCommand":{"enabled":false}}
```

`npm run test:incoming`只使用隔离FakeBot/FakeDSH。实际部署只读检查配置、进程和健康状态；**禁止在真实QQ私聊／群聊发送测活消息验收**。此策略不保证账号不会受到平台限制。不要公开实际网关配置或凭据。
