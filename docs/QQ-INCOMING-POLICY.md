# QQ入站显式诊断消息策略

QQ私聊／群聊收到明确的测活或状态命令时，桥接在解析引用、抓取媒体、执行指令、保存未读和模型唤醒前直接返回。对所有发送者（包括管理员）统一适用，没有会话开关可以绕过。

覆盖`#sl`、`#ping`、`/status`、显式服务器／系统状态查询、独立诊断命令与部分帮助菜单探测。兼容大小写、全角、零宽字符、@与引用段。只检查当前消息自己的文字，普通聊天中讨论这些字符串不据此执行诊断。

自然语言提醒、天气、定时任务，以及原结构化业务指令继续使用原处理器。网页工作台与内部定时任务不经过QQ入站过滤，服务器管理可从工作台操作。此策略减少自动响应入口，不能保证账号不会受到平台限制。

## 必须同时关闭网关内置回复

SnowLuma的`#sl`是网关内置功能，可能在消息到桥接前就回复。只安装桥接过滤不够。请在**自己的**SnowLuma配置中将`statusCommand.enabled`设为`false`（默认及每账号配置均检查），保留网络节点、访问令牌和其他字段。可通过已授权的网关管理面板保存并应用，或持久修改后受控重启**独立的SnowLuma网关进程**；不要因此重建容器、清除QQ数据或重启QQ客户端。

账户配置示意（仅展示需改的字段，不能把整个配置覆盖成此片段）：

```json
{"statusCommand":{"enabled":false}}
```

`swallow=true`只决定是否向下游分发，不能关闭内置回复；增加cooldown也不能保证静默。默认和账号配置存在覆盖关系，应核对最终合并值。

## 验证

运行`npm run test:incoming`，使用隔离FakeBot/FakeDSH验证所有身份、私聊／群聊和多运行模式下零发送／零网络动作／零模型唤醒，并确认业务提醒路径仍可用。原QQ状态回执测试已按新策略改成静默断言。

真实部署只读核对配置、进程身份和本地健康接口。**禁止在真实QQ私聊或群聊发送测活指令验收。** 不公开实际网关配置、凭据、QQ号、会话或数据库资料。
